How to set up the Slack app
  1. Create the Slack app

    Slack opens with everything filled in. Pick your workspace, check the summary, and choose Create.

  2. In the app's menu, open Install App, choose Install to your workspace, then Allow.
  3. Open OAuth & Permissions and copy the Bot User OAuth Token into the bot token box below. It starts with xoxb-.
  4. For Acknowledge and Silence buttons, open Basic Information and find App-Level Tokens. Choose Generate Token and Scopes, give it any name, add the connections:write scope, and generate it. Copy it into the app-level token box below. It starts with xapp-.
  5. Put the channel to post in, such as #alerts, in the box below. For a private channel, invite the app to it first with /invite @maxnines.

Buttons act as the MaxNines user with the same email address as the person pressing them, so everyone needs a MaxNines account with the email they use in Slack. Guests and people from other organizations can't use them. The server connects out to Slack for them, so it doesn't need to be reachable from the internet.

Creating the app by hand instead

At api.slack.com/apps, choose Create New App, then From a manifest. Pick your workspace, choose JSON, and paste this in:

{{ slack_manifest }}

On an Enterprise Grid org-wide install, use the channel's ID rather than its name. It's at the bottom of the channel's details in Slack.

How to get a PagerDuty integration key
  1. In PagerDuty, open the service that should get these alerts, then its Integrations tab.
  2. Add an integration, and choose Events API V2.
  3. Copy its Integration Key into the box above.

Sending a test opens an incident on that service and resolves it straight away, which can notify whoever is on call.

How to set up AlertOps
  1. In AlertOps, go to Configuration, then Integrations. Under Inbound Integrations, choose API and add one using the Custom card, with the escalation policy you want.
  2. Open its rules for opening and closing an alert. Keep the method as POST and the content as JSON.
  3. Paste this in as the sample data: 
    {{ alertops_sample }}
  4. Map alert_id to both Source Name and Source Id, so each alert stays separate. A fixed Source Name would merge them into one.
  5. Map status as the status field. Open an alert when it contains open, and close it when it contains closed.
  6. Map subject and message to the text fields you want, and link to Source URL.
  7. Leave the authorization header off, then copy the integration's URL into the box above. Do this last, as changing its source changes the URL.

Sending a test opens an alert and closes it straight away, which can notify whoever is on call.

How to get a Teams workflow URL
  1. In Teams, open the channel that should get alerts, open its ··· menu, and choose Workflows.
  2. Choose Post to a channel when a webhook request is received, give it a name such as MaxNines, and choose Next.
  3. Check the team and channel, then choose Add workflow.
  4. Copy the URL it shows into the box above. Teams doesn't show it again, though Power Automate does, under the workflow's When a Teams webhook request is received step.

Office 365 connector URLs, on webhook.office.com, have been retired by Microsoft and no longer work. Teams messages don't include the chart, and have no Acknowledge or Silence buttons.

How to get a SIGNL4 webhook URL

Put https://connect.signl4.com/webhook/ followed by your SIGNL4 team or integration secret in the box above.

Sending a test opens an alert and resolves it straight away, which can notify whoever is on call.

How to set up a Telegram bot
  1. In Telegram, message @BotFather, send /newbot, and follow its steps. Copy the token it gives you into the box above.
  2. Add the bot to the group that should get alerts, or send the bot a message yourself for alerts in a private chat. For a channel, make the bot an admin that can post.
  3. To find the chat ID, open https://api.telegram.org/bot followed by the token and /getUpdates in a browser, and look for "chat":{"id":. Group IDs start with a minus sign. A public channel can use its @username instead.

When an alert resolves, the message replies to the one that said it started.

Alerts to send Leave warnings off to keep them off a pager. The channel hears of an alert once it reaches one of these, then of every change until it resolves.
